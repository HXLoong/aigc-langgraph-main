# 节点级测试用例维护与回归平台产品需求文档

## 一、要解决什么问题

现在修改一个节点后，往往要重新跑完整工作流。完整流程依赖 LLM、标的识别服务和业务后端，速度慢，
也容易受外部环境影响。

目标是把一次完整测试中的节点输入和正确输出保存下来。以后修改某个节点，只回归这个节点，
不用再跑整条链路。

## 二、怎么使用

```text
运行完整测试 → 查看当前任务或历史报告 → 选择节点 → 人工确认输出
→ 保存为 JSONL → 以后直接运行该节点并比较结果
```

## 三、需要提供的功能

| 功能 | 说明 |
|---|---|
| 获取节点 | 从 Langfuse 读取一条用例经过的业务节点，并显示所属轮次 |
| 筛选节点 | 按产品、节点类型、是否支持回归进行筛选 |
| 查看数据 | 查看节点输入和实际输出 |
| 人工标注 | 可以选择部分字段，也可以标注整个稳定输出对象 |
| 保存用例 | 保存到 `tests/fixtures/nodes/<产品>/<节点>.jsonl` |
| 单节点回归 | 直接运行一个节点，显示通过、失败和字段差异 |
| 历史标注 | 当前任务和历史测试报告使用同一套标注页面 |

标注范围覆盖互换、期权等业务链路中的全部业务节点。

节点数量不得硬编码，注册表也不是展示白名单。工作台从 Langfuse observation 动态发现
当前实际经过的 LangGraph 节点；新节点无需修改固定数量或名称清单即可查看。

已知节点可在注册表显式声明稳定字段和安全回放契约。自动发现的新节点若有公共稳定输出，
可进行字段级或对象级标注，但默认禁止回放；只返回动态 `trace`、私有中间态或空对象的
节点显示为“仅查看”，服务端也禁止保存无意义的空断言。只有显式声明为无写副作用且配置
单节点执行入口后，才能启用回放。

字段级标注是默认方式。例如只检查标的代码、价格类型和跟量比例，不检查耗时、Trace ID 等
每次都会变化的字段。

## 四、JSONL 格式

JSONL 每行是一条节点测试用例。以下是简化示例：

```json
{
  "id": "swap-place-001",
  "node_name": "swap_place_order",
  "input": {"raw_text": "长飞光纤清仓，市价跟量9%"},
  "expected": {
    "mode": "fields",
    "fields": {
      "/expected_action": "place",
      "/place_params/orderList/0/placeOrderWindCode": "长飞光纤"
    }
  },
  "replay": {"enabled": true, "side_effect": "read"}
}
```

实际保存时还会记录来源用例、轮次、Langfuse Trace、标注人和标注时间，方便追溯。

运行方式：

```bash
# 运行全部节点用例
python -m harness node-run --data tests/fixtures/nodes
```

节点回归直接运行真实节点，并调用真实 LLM、标的识别服务和只读业务接口。

## 五、安全要求

- 下单、确认、撤单等写操作节点只能查看和标注，禁止直接回放。
- JSONL 中不能保存 API Key、Secret、Cookie 等敏感信息。
