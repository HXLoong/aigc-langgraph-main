# ADR 编写规范与编辑权限审核（2026-10-10）

## 范围与结论

审核工作区当前的 32 篇 ADR（0000–0031），以本次更新的 [ADR README](../adr/README.md) 为准：Nygard 核心结构、可选备选方案 / 相关链接、状态与章节编辑权限、稳定标识及历史保留。

**结论：尚不能宣称当前 ADR 集合符合规范。** 编号完整且唯一，基础元数据齐全，但存在决策效力冲突、同编号实质改写、治理规则冲突、替代关系缺失，以及失效引用。章节是否齐全只是其中一项，不足以证明历史或决策合规。

本次只更新 README 和报告索引，不修改 ADR 正文或状态，不批准新的架构决策，也不改变代码。旧文档按 README 的兼容规则解释权限，不因缺少标准标题而允许 AI 重排或重写。

### 方法与限制

- 逐篇阅读 32 篇 ADR，核对标题、元数据、背景、决策、后果、备选方案、关系及 README 索引。
- 用只读文本盘点统计二级标题；该统计反映显式章节，不把缺少标题直接等同于缺少全部语义。
- 对照用户指定的历史提交 `df0c4a261082758790c399b79af7158d5e210ced`，按编号比较 0000–0030 的文本，并详细检查 0003、0020 的差异。这只是两个快照的比较，不是所有历史提交的完整不可变性审计。
- 执行既有 ADR 引用与文档布局检查。未验证所有外部链接、页内锚点、Java 实现、业务数据或各篇“已完成”的声明，也不能从 Git 作者推断编辑是否由 AI 完成。
- 新规范不追溯认定旧格式本身违规；格式差异是迁移审核项。已接受决策仍不应为套模板而被覆写。

### H1：旧治理决策仍要求删除 / 改写历史，与本次规范冲突

证据：[ADR 0030](../adr/0030-goal-restatement-native-langgraph-dataset-eval-harness.md) 第 22 行明确要求“只写现行结论，被取代的决策直接删除”；第 42 行把追认作为状态标签；第 48 行将“删除被取代的 ADR”列为已选方案。

其他规则仍有旧口径：[文档地图](../README.md) 第 43 行要求 ADR“只写现行结论”，第 69 行的通用文档维护规则要求过时内容直接改或删；`.claude/rules/git-workflow.md` 第 46 行的提交示例也仍使用“精简 ADR，只保留现行决策”。后者是示例，不单独作为删除授权。

**建议**：维护者以新 ADR 记录治理方式变化，明确仅替代 0030 的相关治理条款及范围，再授权更新前序状态 / 关系与公共规则真源。不得直接把 0030 的旧决策改写成新规则。本次未创建新 ADR，也未修改用户已有的公共规则改动。

## 结构与内容问题

### S1：历史正文没有明确分离核心要素

缺少显式背景标题：0004、0006、0007、0008、0009、0010、0013、0016、0017、0018、0022、0031。

缺少显式后果标题：0000、0003、0004、0006、0008、0010、0013、0016、0017、0018、0019、0022。

0031 有问题说明、设计约束、职责和后果，但缺少标准的背景 / 决策标题。历史存根使用“原决策”，不能因为名称不同而把它当成可编辑区域。0009 在“决策”中已经说明外部背景；0007 在首段解释了分类问题。

**处理方式**：这些是结构差异或内容完整性问题，不是批量补写授权。已结束 ADR 的缺项应优先从原始证据确认；不能由 AI 事后编造当时的背景或代价。

### S2：部分“后果”只有收益或混入动态状态

- 0001 第 59–63 行只有已兑现的收益，缺少明确的实施成本 / 风险；其中有已落地声明，本次未核实。
- 0014 第 47–50 行只列统一后台和合规收益，未明确记录自托管运维或集成代价。
- 0002 第 20–30 行、0003 第 33–35 行、0011 第 16–20 行、0023 第 53–55 行承担持续更新的现状盘点，容易与工作计划漂移。
- 0024 是多领域的总纲，0030 同时承担目标、评测门与文档治理。后续实质演进宜使用聚焦的新 ADR，而不是继续把每个领域的新结论合入这些旧正文。

负面后果应如实写出，不为补齐模板而编造；现有正文保持不动。

### S3：状态不是“批准证据”，作者也不等于批准者

32 篇有作者，但未显式区分决策者与记录作者。不能推断这些 ADR 未经批准，也不能由 AI 补造批准人或批准日期。

0024 的“已冻结”在正文中已有“后续决策开新编号”的解释，属于历史保留要求，不是额外生命周期状态。0025 的“追认”是记录方式，不是比“已采纳”更高的效力。本次 README 已解释二者，不修改原头部。

## 后续处置边界

本次实现完成的是 README 规范和审核记录，不是 ADR 全量整改。历史正文、公共规则同步、新的治理 ADR、替代范围裁决、链接修复及章节门禁均未实施；不宣称自动检查通过或全量合规。
