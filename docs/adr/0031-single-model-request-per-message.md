# ADR 0031 · 单条消息全链路最多一次模型请求

- 状态：已采纳（目标约束，代码待重构）
- 日期：2026-09-24
- 关系：修订 ADR 0001 D5、0024 D3、0026 D2、0027 D2；产品划分遵循 ADR 0007，确认、提示词、标的与单动作边界继续遵循 ADR 0021、0023、0025、0028。
- 作者：图灵科技

同一条指令被产品分类、意图识别、参数提取和候选选择重复解释，增加了调用次数与语义不一致的机会。每条用户消息的完整业务处理链最多发起一次模型请求，必要的语义判断在这一次请求中完成，后续采用确定性校验和业务执行。调用减少带来的准确率、成本和延迟变化须通过评测验证。

## 约束

1. **按消息轮次计数。** 从本条用户消息进入主图到回复结束，所有主图、嵌套子图、工具封装、并行分支和循环共享一次模型请求额度；允许零次。多订单、多图片、多 Excel 行不增加额度；用户的新消息开始新一轮，幂等回放不重新解析。
2. **约束真实请求。** 可以保留多个互斥的 LLM 解析节点，但同一轮最多执行其中一个且最多发起一次模型请求。禁止通过合并函数、逐订单/逐附件处理、Agent 工具循环、并行调用或新增模型代理服务规避额度。
3. **全部 LLM 重试关闭。** 模型请求一经发起即占用本轮额度；超时、限流、输出解析或证据校验失败都不得再次请求，不允许补问、输出修复、备用模型或提示词切换重试。错误沿现有 cascade 机制停止业务提交并返回可追踪的失败结果。SDK、图节点和外层封装均不得重复调用模型；外部网关自身行为需按其契约独立核查。
4. **覆盖全部产品与附件。** 适用于互换、期权、期权平仓和其文本、图片、Excel 输入。约束本项目发起的模型请求；快速询价、存量查询仍走既有入口，不假设 Java / GOATS 服务内部的模型调用次数。

## 解析职责

- 先完成无需模型的会话保护、入口分流、引用读取、附件读取和可确定的产品路由。需要后端只读数据作为模型上下文时，先用确定性依据获取；不得先用一次模型分类，再查数据后第二次提取。
- 产品已确定时，可以进入该产品的专用联合解析；产品不明确时，唯一一次请求联合判断产品、单一业务意图并提取必要的原文候选。不得先只输出产品，再由产品子图调用模型。
- 有歧义的对手/标的候选选择与参数抽取共用本次解析结果；明确的编号或引用选择继续由代码处理。保持单业务动作、多订单共用该动作，不产生多动作编排。
- 后续图节点保留证据校验、归一化、字段锁定、权限与确认范围校验、Java 执行、回复与持久化等职责。模型不得直接取代最终交易参数校验；证券识别、业务默认值和真实业务回执继续以 Java 为权威。
- PromptSpec、Pydantic 输出契约、Git 提示词真源及业务子图边界继续保留。共同输出需表达产品、意图及对应候选约束，不能只是将旧提示词拼成一个无边界的大提示词。
- 用户下一条明确确认并引用当前订单的消息是新轮次，继续执行文本二阶段确认；本规范不合并发起与确认，也不放宽写操作条件。

## 附件边界

- Excel 先由代码读取并保留单元格来源，在一次模型请求中批量提取；不得逐行调用。
- 图片由支持本条消息全部图片输入的视觉模型一次输出候选及来源；不得先单独调用模型 OCR 再调用另一模型抽取，也不得逐图调用。文本与图片允许使用不同模型，但同一轮仍只调用一个。
- 图片原件及图片定位是证据来源，模型给出的转写不能声称已被代码独立验证为图像真值；原文候选与来源记录仍须可追溯，图片字段准确性纳入业务样本验收。
- 输入超出所选模型容量、输出无法完整承载订单，或部署缺少相应模型能力时，停止处理并明确提示用户调整输入；禁止静默截断、漏订单或分批追加请求。输入容量按模型能力设置，具体阈值经测试确定，不在 ADR 写死。

## 错误与验证

只读后端查询可独立有限重试，写类节点继续不自动重试。模型解析与可重试的查询必须分开，后端失败不得导致已执行的模型重新运行。不得全局关闭所有 IO 重试来替代正确拆分职责。

验收须同时覆盖调用额度和业务质量：检查图中的串行与并行路径，并在模型请求边界验证每轮实际请求次数不超过一；覆盖歧义产品、引用、多订单、多附件、零调用、失败和后端重试场景。业务质量继续遵守 ADR 0030 的数据集与节点级评测门，不通过扩大拒绝范围、漏字段或漏订单换取额度合规。合并节点后同步迁移 PromptSpec、Harness 注册、节点 fixture 和流程文档。

## 后果

一次联合解析降低了重复解释的机会，但扩大了该次请求的输入输出契约；必须用按产品与意图组织的契约和回归数据控制复杂度。关闭重试会使瞬时模型错误直接影响当轮结果，失败率与延迟基线需重新测量，不能沿用“重试后”的可靠性假设。

期权平仓继续作为独立业务子图，意图与动作处理仍有清晰边界；独立节点不等于独立模型调用。产品路由保留既有规则优先级：订单号优先于关键词，引用卡片、附件类型及上下文作为判定依据；上下文继承不增加模型调用，仍无法确定产品或意图时进入统一 unknown 兜底。路由来源与候选证据必须可追踪。
