# ADR 0011 · 期权子图拆分意图识别与分意图参数提取

- 状态：已采纳
- 日期：2026-05-10
- 关系：抽取节点的输出契约由 [ADR 0027](./0027-field-evidence-contract.md) 收敛为原文候选
- 作者：图灵科技 + Tony

## 背景

原 Dify 工作流把期权意图分类与完整参数抽取塞进一个约 2870 行的提示词，分类与抽取相互干扰，回归面与提示词规模不可控。

## 决策

期权处理分两个阶段：**先识别业务意图，再按意图进入专用参数提取节点**；期权平仓继续归独立的 close 子图。这一边界不依赖具体意图数量：增删意图时只调整第二阶段节点，不把分类与所有 DTO 重新合回一个巨型提示词。

## 现状

`app/subgraphs/option/graph.py`：1 个意图节点 + 7 个提取节点一一对应 7 个业务意图（新询价、按报价下单、确认下单、撤销下单申请、申请撤单、确认撤单、查询订单状态）+ 兜底节点。已有订单的改参统一归"按报价下单"。

其中 4 个只需提取期权单号的节点已改为确定性代码（`app/subgraphs/option/order_id.py`），不再调用 LLM；现役期权提示词只剩意图识别与询价抽取两份。

## 备选方案

- **保留单个巨型节点**：分类与参数耦合，不可维护。
- **两阶段 + 分意图提取（已选）**：分类边界稳定，提取节点可随业务演进。
- **三阶段（意图 → 草稿 → 校验）**：额外调用与状态复杂度暂不值得。

## 后果

- 每次期权调用多一次分类 LLM 调用，成本以实测 P95 观察。
- 意图枚举、`_INTENT_TO_NODE`、提示词与数据集必须同步变更。
- close 子图保持独立，不得把平仓意图并回 option。
