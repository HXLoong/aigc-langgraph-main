# ADR 0012 · 标的查询走后端 HTTP API，弃用数据库直连

- 状态：已采纳（"后端是标的唯一真源"的结论由 [ADR 0025](./0025-instrument-resolution-delegated-to-backend.md) 推广到整个识别链路；LangGraph 侧查询调用点已退役）
- 日期：2026-05-10
- 作者：图灵科技 + Tony

## 背景

早期为摆脱 VPN 依赖，曾把标的查询从后端 HTTP 接口改为直连标的池数据库表。这次"优化"丢失了后端检索打分中的非平凡业务规则（多关键词加权、精确 / 模糊分流、退市过滤、配额分配），导致"找得到但找不准"。

## 决策

恢复走后端 HTTP API，**后端标的服务是标的查询的唯一真源**；LangGraph 不直连标的数据库。

## 理由（已被实证）

后端曾调整检索配额与结果上限，HTTP 方案零改动自动跟上。"在 LangGraph 里重写后端规则"必然产生两份会漂移的实现。

## 备选方案

- **保留直连、Python 重写打分逻辑**：双实现易漂移，重写出错概率高。
- **恢复 HTTP（已选）**：单一真源，与后端规则升级自动对齐。
- **双路径开关**：运维复杂度增加，无收益。

## 后果

- 通用原则：任何把后端逻辑搬进 LangGraph 的"性能优化"，必须先评估会丢失哪些业务规则。
- 2026-09-20 起标的识别整体由 Java 负责，LangGraph 只传原文（ADR 0025）；`app/tools/ticker_client.py` 为遗留客户端，已无业务调用方，去留待定。直连相关的配置项已于 2026-09-22 清理。
- 原端点与业务规则清单见 [实施记录归档](../archive/history/adr-implementation-log-2026-09.md)。
