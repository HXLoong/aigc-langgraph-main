# ADR 0027 · 字段来源契约：保留提取证据，业务值由 Java 校验

- 状态：已采纳（Java 请求前类型兼容清洗；业务值仍由 Java 校验）
- 日期：2026-09-24
- 关系：输出描述见 [ADR 0023](./0023-prompt-as-code-langgraph.md)，标的职责见 [ADR 0025](./0025-instrument-resolution-delegated-to-backend.md)，单次处理见 [ADR 0021](./0021-text-confirm-replaces-interrupt.md)，模型额度见 [ADR 0031](./0031-single-model-request-per-message.md)
- 作者：图灵科技 + Tony

## 背景

字段值需要与用户输入、引用和附件建立可追踪关系，但来源记录不等于 LangGraph 要再实现一套交易数值计算与校验。用户表达的提取、现有接口序列化和 Java 的业务处理应分开。

## 决策

### D1 · 一次提取，同时保留原文与来源

每个字段保留提取值、对应原文、来源类型与定位信息；来源可以是本次消息、用户引用、有效历史上下文或附件位置。模型完成业务语义提取所需的判断，输入与输出含义由 PromptSpec 和 Pydantic 字段描述定义，并遵守 ADR 0031 的单次模型请求上限。

标的名称、代码或月份表达仍按原文或用户明确选择提交（ADR 0025）。其它参数按照既有接口要求表达，但模型输出只是待提交值，不是已验证的交易事实；缺失值不由 LangGraph 补业务默认。

### D2 · 保留结构与来源检查，不做业务数值校验

- LangGraph 检查结构化输出、字段来源是否存在、文本证据与对应来源的关联、引用选择与本次订单范围的一致性。
- 不做数字边界匹配、金额 / 数量 / 比例范围校验、精度重算或业务合理性校验；不因数字不是原文中一个独立词元而触发本地拒绝。
- 本阶段附件来源为 Excel 单元格与位置；图片暂不处理，不产生图片字段或 OCR 转写证据。
- 结构或来源检查失败写入 E2 并停止本次提交，不修复输出或再次请求模型。空占位不作为需要编造来源的业务事实；D3 的参数字符串 JSON 解码失败单独按 Dify 兼容处理。Java 负责业务数值、权限、可交易性与状态校验。

### D3 · Java 请求前类型兼容清洗

普通期权、互换、平仓的参数准备与 Java 提交之间设置独立 Code 清洗节点，共用接口类型规则。模型候选保留原始标量类型，避免结构化模型把 `true` 转成整数 `1`，或在清洗前因 `100万` 整体失败。产品、意图、身份与对象形状仍使用严格契约。

- 金额、价格、数量和比例按 Java 真实字段类型检查；纯数字字符串允许无损装配。整数必须无小数部分且能由 Integer/Long 表达，有限十进制值不做业务范围或精度截断。Boolean 不能当作整数。
- 不兼容的可选字段省略，不发送 null，不填 0，不换算单位。原本的 0、false、负数保留，业务有效性由 Java 判断。Java 声明为 String 但要求数字内容的平仓金额也按此处理。
- 完整的空字符串、空白、null 字面量与 JSON null 作为未提供值省略。Java 明确支持的百分比、期限与短时间格式保留，不补日期，不猜枚举，不恢复旧订单参数。
- 每笔订单及其顺序保持不变；错误身份或损坏订单结构停止提交，不能通过删除订单/身份扩大或改变范围。已有订单补参、修改和确认中的错误业务字段也省略，其余参数继续提交，由 Java 合并旧值、校验并生成回执。
- 此阶段只解决接口接收能力，不增加单位换算、比例计算、时间补全或业务默认值。快速询价和存量入口不纳入这次普通参数清洗。

**字符串 JSON 兼容**：清洗入口收到参数字符串时按 Dify 解码；解码失败或空字符串回退为空对象并继续调用 Java，不补 `unknown_intent`。期权发送 `type=null / operate=null / orderList=[]`；互换发送 `type=null / orderList=[]`；平仓保留独立的原意图，发送 `closeOrderReqVO={} / operate="" / orderList=[] / optionRfq={}`。兼容请求保留这些显式 null/空容器，HTTP 异常显示“交易指令服务暂不可用”，原始错误入审计。

这项容错仅属于清洗入口的参数字符串解码，不吞掉模型网络错误、输出超限、合法 JSON 的结构错误或来源错误，不增加模型请求或交易重试。

### D4 · 字段来源记录与锁定

- `FieldRecord` 保留提取值、来源、原文、置信度与锁定信息；置信度只作诊断，不代替来源或业务校验。
- 同次指令中，被选中的订单与字段不能被后续节点静默删除或覆盖。清洗是有记录的传输投影：原解析与 FieldRecord 保留，独立出站副本记录路径、原值、目标类型、省略/转换原因和最终值；字段锁在清洗前核对，提交时不得把省略值从原账本重新补回。独立节点回放同样核对字段锁。
- 字段锁定保护输入和选择的一致性，不意味着该值已经业务校验通过，也不依赖 Code 产出归一化值。

### D5 · 本次动作与引用选择

按 ADR 0021，LangGraph 不建立强制二阶段流程。现有确认类意图作为独立输入处理：用户本次明确表达动作，所提交的订单号与引用、序号或合约选择一致；否定、疑问和条件表达不自动变成确认动作。

历史记忆与程序生成的引用不能代替用户本次选择。LangGraph 提取订单号及适用的显式参数；Java 读取订单、合并参数、校验并处理。本节不要求所有交易先申请再确认，也不把识别到确认口令当成交易成功。

## 备选方案

- **模型提取后再由 Code 归一化并校验业务数字**：本阶段不采用，避免在 LangGraph 重复解释业务数值。
- **不记录来源，只交模型最终结论**：无法复核误提取与串单，不采用。
- **提取值 + 原文来源 + Java 业务校验（已选）**：保留可追踪性，业务有效性以 Java 为权威。

## 后果

字段准确性仍需确定性数据集断言和真实后端验收保证。API/Harness 比较实际出站参数，原始提取值与清洗记录留作审计；不以省略字段掩盖标注缺口或降低断言。实现和验收见[工作计划](../work-plan.md)。
