# ADR 0021 · 文本二阶段确认替代 LangGraph interrupt，并接线持久化 checkpointer

- 状态：已采纳
- 日期：2026-08-27
- 关系：取代早期 interrupt 拦截方案（原 0006 号，已删除，其风险规则并入本篇 §1）；确认范围校验见 [ADR 0027](./0027-field-evidence-contract.md) D5；建表口径见 [ADR 0009](./0009-mysql-version-and-tdsql-compatibility.md)
- 作者：图灵科技 + Tony

## 背景

早期方案计划用 LangGraph `interrupt_before` 拦截写 + 资金类节点，但核查发现其执行载体从未存在（无 interrupt、生产图未接 checkpointer、无恢复端点）。与此同时，**文本"确认"路径已在实际工作并被数据集覆盖**：客户回复确认 → 意图识别 → 确认节点执行写操作。

## 决策

### 1. 文本二阶段确认为正式确认机制

```
客户发起 → 抽取参数 → 后端生成待确认卡片 → 本轮结束
客户回复"确认 + 订单引用" → 路由 → 确认节点 → 真正写后端
```

不实现 `interrupt_before` 与按钮回调端点。理由：文本路径已被验证且被数据集覆盖；按钮回调需要企微与 Java 新增联调面；二阶段在业务上等价（写操作都需客户显式二次表达）；"单轮结束、新消息重新起图"的模型更简单。

哪些意图必须走二阶段，按**"是否产生不可逆的后端写操作 + 是否涉及资金或合约履行"**两条轴判断：

| 类型 | 示例 | 需要二次确认 |
|---|---|---|
| 纯查询 | 持仓、订单状态、报价 | 否 |
| 写操作但低风险 | 修改无金额影响的字段 | 否 |
| 写操作 + 资金 / 合约 | 下单、撤单、改单、平仓 | **是** |
| 已确认的二阶段意图 | 确认下单 / 确认撤单 / 确认平仓 | 否（本身就是确认） |

新增产品（如结构化产品）时，必须先按上表标注每个意图。

### 2. checkpointer 接线

多轮状态持久化是生产正确性要求（跨进程 / 重启不失忆），与 interrupt 无关：

- 配置 `use_mysql_checkpointer`：**生产必须为 true**，否则启动即失败；启用后初始化失败同样直接报错，不静默降级。
- 开发 / CI 默认关闭，避免测试依赖 MySQL 与残留状态导致结果翻转。
- 表由 `sql/init.sql` 创建，应用启动只做只读校验（ADR 0009）。回归测试：`tests/test_checkpointer_wiring.py`。

## 备选方案

- **补齐 interrupt 全套**：需企微按钮回调 + Java 配合 + 恢复语义管理，成本与风险不成比例。
- **不接 checkpointer**：重启失忆，生产不可接受。
- **checkpointer 默认全局开启**：本地与 CI 测试被 MySQL 绑定并出现状态残留。

## 后果

- 确认类意图的数据集覆盖是确认链路的主要回归防线；七条最终确认路径统一要求"明确动作 + 引用当前订单"（ADR 0027 D5）。
- 现场部署 checklist：执行 `sql/init.sql` 后首次启动校验 checkpoint 表通过。
- 若未来业务方强烈要求按钮式确认，再开 ADR 评估 interrupt；届时 checkpointer 已就位，增量只剩回调端点。
