二、Reducer：覆盖 vs 累加

class AgentState(TypedDict, total=False):
    product_type: ProductType                      # 覆盖型：后写的赢
    trace: Annotated[list[TraceEntry], merge_by_id]            # 按 id 合并，并行不重复
    history_messages: Annotated[list[Message], merge_history]  # 多轮合并，不丢不重
app/graph/state.py

判断口诀："多个节点都要往里写、且不能互相冲掉"的字段 → 加 reducer；单值结论字段 → 不加。

四、项目十二铁律（review 必查）

  1. 提示词不硬编码——load_prompt("swap", "intent") 从 app/prompts/**/*.md 加载
  2. LLM 输出必须 with_structured_output(PydanticModel)，绝不手工 json.loads
  3. 每个节点 @safe_node——异常降级到 state["error"]，图不崩
  4. State 字段先在 app/graph/state.py 声明再用
  5. TDD 强制——先写失败测试（RED）再改代码（GREEN）
  6. cascade 防御——任何条件路由第一行检查 state.get("error")
  7. 标的原文交 Java 后端识别，LangGraph 不维护证券清单（ADR 0025）
  8. 后端调用走 Protocol（Swap/Option/Message 客户端），禁止节点里直接 httpx.AsyncClient
  9. 不在 main 直接改业务子图——feature 分支 + 中文 PR
  10. 不掩盖后端真实响应（P0 红线）
  11. 不硬编码业务数据字典——LLM 推断 + 后端校验（P0 红线）
  12. Mock 要 patch 使用点，不是定义处（tests/CLAUDE.md）
