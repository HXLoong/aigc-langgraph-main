六、读图要点

cascade 出口对照表（每层各自设防）

error 写入的位置由谁拦截降级去处
ingest / intent_route主图 _route_after_intent 第一行主图 fallback 节点
子图 *_intent 节点子图 _route_after_*_intent 第一行子图 *_unknown 节点
子图业务节点（如 swap_place_order）无路由拦截——业务节点后是到 END 的无条件边error 随 state 带到 render，由它输出友好话术

四个必记结构事实

  1. 所有路径殊途同归：4 个分支（3 子图 + fallback）跑完都走无条件边进 persist → render → END——所以任何失败最终都有回复、都有 checkpoint
  2. 主图 fallback ≠ 子图 unknown：进了子图之后再失败，主图 fallback 不会执行（第 02 课路由推演的陷阱）
  3. 三个子图同构：intent → 路由表 → 业务节点 + unknown 兜底。看懂 swap 就看懂全部；差异只在意图数量和"意图多对一合并"（option 9→5、swap 的 confirm 3→1）
  4. ticker 是工具不是分支：它被业务节点通过 resolver 调用，输出 tickers 写回同一份 state——主图和三个子图的任何一条边都不通向它
