LangGraph 团队实战课 · 第 01 课

把第一张图跑起来：State / Node / Edge

30 行代码跑通一个带循环的 LangGraph 图。学完这一课，你就掌握了看懂 app/ 下所有图代码的最小前置。

编写者：图灵科技预计用时：25 分钟前置：会 Python + async 基础
为什么先学这个（对齐任务） 我们正把 Dify 工作流全量重构为 LangGraph。Dify 里"节点 + 变量 + 连线"这套心智，在 LangGraph 里对应的就是本课的三个概念——State（变量）、Node（节点）、Edge（连线）。区别是：Dify 的变量是全局命名空间，LangGraph 的 State 是显式声明的 schema。这一个转变，是 Dify 老成员最需要跨过的一道坎。

1. 先跑起来（10 分钟）

把下面 30 行存成 hello_graph.py（放本仓库根目录即可，环境已装好 langgraph），跑一遍：

import asyncio
from operator import add
from typing import Annotated, TypedDict
from langgraph.graph import END, START, StateGraph

# ① State：类型化 dict，节点间传数据的唯一载体
class State(TypedDict, total=False):
    counter: int                       # 普通字段：后写的覆盖先写的
    log: Annotated[list[str], add]     # reducer 字段：用 + 合并（list 追加）

# ② Node：async 函数，读 state，返回"要更新的字段"（partial dict）
async def increment(state: State) -> dict:
    n = state.get("counter", 0) + 1
    return {"counter": n, "log": [f"now {n}"]}

# ③ 条件路由函数：同步纯函数，返回下一站的名字
def is_done(state: State) -> str:
    return "done" if state.get("counter", 0) >= 3 else "again"

# ④ Graph：组装 → 编译
g = StateGraph(State)
g.add_node("inc", increment)
g.add_edge(START, "inc")
g.add_conditional_edges("inc", is_done, {"again": "inc", "done": END})
graph = g.compile()

# ⑤ 执行
result = asyncio.run(graph.ainvoke({"counter": 0}))
print(result)
# {'counter': 3, 'log': ['now 1', 'now 2', 'now 3']}
来源：docs/training/langgraph-handbook.md 第 2.11 节（可运行验证过）

盯着输出想一件事：counter 最后只剩 3，而 log 攒下了三条。同样被节点写了三次，为什么一个覆盖、一个累加？答案就是 Annotated[list, add] 里那个 reducer——这是本课唯一需要"记住"的机制。

2. 三个概念对照到真实项目（10 分钟）

State：从玩具到 AgentState

打开 app/graph/state.py，真实的 State 长这样（节选，字段有删减）：

class AgentState(TypedDict, total=False):
    # 入口：ingest 节点写入
    raw_text: str
    conversation_id: str
    # 历史：reducer 累加，多轮对话不丢
    history_messages: Annotated[list[Message], add]
    # 业务路由
    product_type: ProductType        # "swap" | "option" | "option_close" | "unknown"
    intent: str
    # 业务对象：按业务聚合，不按节点铺开（ADR 0001 D6）
    place_params: dict[str, Any] | None
    # 工程层：每个节点追加自己的痕迹
    trace: Annotated[list[TraceEntry], add]
    error: ErrorInfo | None
app/graph/state.py（真实代码节选）

和 Dify 的关键差异：Dify 里任何节点可以用 {{#节点ID.变量#}} 读任何上游输出（全局命名空间）；LangGraph 里节点只能读 AgentState 中已声明的字段——字段拼错或没声明，mypy 直接报错，PR 合不进去。

Node：本项目的节点长什么样

规则和玩具例子完全一样（读 state → 返回 partial dict），只多一件外衣 @safe_node：

from app.graph.state import AgentState

模式出处：app/subgraphs/swap/intent.py + app/graph/safe_node.py

@safe_node 的内部实现和 cascade 防御是第 03 课的主角，今天只需要记住：项目里所有节点都戴这顶帽子，写节点时不要自己 try/except。

Edge：主图的真实条件路由

def _route_after_intent(state: AgentState) -> str:
    if state.get("error") is not None:      # cascade 防御：永远第一行
        return "fallback"
    pt = state.get("product_type", "unknown")
    return "fallback" if pt == "unknown" else pt
app/graph/main.py（主图一级路由）

注意两条纪律：路由函数是同步纯函数（不 await、不调 LLM、不发 HTTP——需要这些就放进上游节点，把结论写到 state）；返回的字符串必须是映射表里的 key。

Dify 老成员最容易踩的坑 Dify 的 if-else 节点是声明式配置（comparison_operator: contains），大家习惯"分支逻辑放配置里"。LangGraph 的路由函数是任意 Python——能力更强，但也因此有纪律：路由只做判断，不做 IO。把"判断需要的信息"提前在节点里算好写进 state。

4. 小测（拿到全对再进第 02 课）

自测 · 4 题

1. 节点函数正确的返回方式是？

节点返回 partial dict，框架负责合并；mutate 入参和返回完整 state 都是铁律反例（handbook 第 2.2 节）。

2. trace 字段为什么要声明成 Annotated[list[TraceEntry], add]？

没有 reducer 的字段被后写的节点直接覆盖；trace / history_messages 是"人人都写"的字段，必须累加（app/graph/state.py）。

3. 条件路由函数里，哪件事是被允许的？

路由函数是同步纯函数，只读 state。LLM/HTTP 放上游节点做完、把结论写进 state（.claude/rules/langgraph-patterns.md）。

4. 玩具例子里 inc 节点跑了 3 次，如果把 log 的 add reducer 去掉，最终 log 是什么？

无 reducer 的字段是覆盖语义——这正是"覆盖 vs 累加"的核心区别，也是多轮对话字段必须加 reducer 的原因。
