# 领域文档

各工程技能在探索代码库时，应按本文件的约定读取领域文档。

## 开始探索前，先读这些文件

- **`CONTEXT.md`**（仓库根目录）
- **`docs/adr/`** — 读取与当前工作区域相关的架构决策记录（ADR）

如果上述文件不存在，**静默跳过即可**，不要提示缺失，也不要主动建议创建。这些文件由 `/grill-with-docs` 技能在实际解决术语或决策时懒创建。

## 目录结构

单一上下文仓库（Single-context）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-*.md
│   └── 0002-*.md
└── app/
```

## 使用术语表中的词汇

在输出内容（issue 标题、重构提案、假设说明、测试名称等）中提到领域概念时，使用 `CONTEXT.md` 中定义的术语，不要改用术语表明确标注为"避免使用"的同义词。

如果所需概念在术语表中不存在，这是一个信号——要么你在使用项目未采用的语言（请重新考虑），要么确实存在术语空缺（记录下来，留给 `/grill-with-docs` 处理）。

## 标记 ADR 冲突

如果你的输出与现有 ADR 相悖，请明确指出，而不是静默覆盖：

> _与 ADR-0007（事件溯源订单）冲突——但值得重新讨论，因为……_
