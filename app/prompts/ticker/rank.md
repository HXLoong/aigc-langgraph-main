## 任务
根据用户输入的关键字，对给定的标的列表进行过滤和相关性排序。

标的列表是一个 JSON 数组，每个元素包含以下字段：
- windCode：标的代码（如 0700.HK、ZN_S.SHF）
- insShtDesc：标的简称（如 TENCENT、SHFE锌次活跃）
- insLngDesc：标的长名（如 SHFE锌次活跃）
- insFamily：标的类型（如 EQUITY、FUTURE、FUND）

- exchange：交易所（如 HKEX、DCE、OTC）

## 重要前提
标的列表来自数据库模糊搜索，搜索条件是从关键字中提取的子串（数字片段、名称片段等）对 windCode、insShtDesc 等字段做子串匹配。因此列表中很多标的仅仅是因为代码或名称碰巧包含了某个子串而出现，并不代表它们与用户的搜索意图相关。你的核心职责是识别并过滤掉这些巧合匹配，只保留与用户搜索意图真正相关的标的。

## 第一步：理解用户搜索意图

在评估任何标的之前，先分析关键字的完整语义，确定用户真正要找的是什么。

关键字可能包含多个组成部分，需要综合理解：
- 品种/公司名称：如"螺纹钢"、"腾讯"、"贵州茅台"
- 标的代码：如"0700"、"AAPL"、"600519.SH"
- 期货合约月份标识，有两种格式：
  - **月份字母+YY格式**（优先级更高）：如"Z26"表示2026年12月，"N26"表示2026年7月。月份字母码：F=1月, G=2月, H=3月, J=4月, K=5月, M=6月, N=7月, Q=8月, U=9月, V=10月, X=11月, Z=12月
  - **YYMM纯数字格式**：如"2601"表示2026年1月，"2503"表示2025年3月
- 行业/概念：如"新能源"、"半导体"

当关键字同时包含名称和数字时，需要判断数字的角色：
- "2503螺纹钢"：核心意图是"螺纹钢"，"2503"是合约月份修饰符（2025年3月），用户要找螺纹钢期货合约
- "0700腾讯"：核心意图是"腾讯"，"0700"是港股代码，两者指向同一标的
- "600519"：核心意图就是这个代码本身对应的标的

## 第二步：逐个评估标的相关性

对列表中的每个标的，判断它是否与用户的核心搜索意图真正相关。

请充分利用你对全球金融市场的预训练知识进行判断：
- 标的所属的公司、品种、行业、概念是否与关键字的核心意图匹配
- insShtDesc、insLngDesc 与关键字的语义关联
- windCode 与关键字的代码部分是否存在有意义的匹配（非巧合）
- 同一集团的子公司、关联公司、上下游产业链也视为相关

### 关键：区分真正匹配与巧合匹配

windCode 或名称中出现关键字的子串，不一定代表真正的关联。必须判断这种重合是有意义的还是纯属巧合。

真正匹配：
- 关键字"0700腾讯"，标的 windCode "0700.HK"、insShtDesc "TENCENT" → 代码和名称都指向腾讯
- 关键字"贵州茅台"，标的 insLngDesc 包含"贵州茅台" → 名称直接匹配
- 关键字"沪铜2601"，标的 windCode "CU2601.SHF"、insShtDesc "沪铜2601" → 品种和合约月份都匹配

巧合匹配（应过滤）：
- 关键字"2503螺纹钢"，标的 windCode "2503.HK"（某港股） → "2503"在关键字中是合约月份，在 windCode 中是股票代码，含义不同，且该港股与螺纹钢无关
- 关键字"2503螺纹钢"，标的 windCode "A2503.DCE"（豆一期货2503合约） → 合约月份碰巧相同，但品种是豆一不是螺纹钢
- 关键字"2503螺纹钢"，标的 windCode "250301.OF"（某基金） → "2503"只是基金代码的前缀巧合
- 关键字"沪铜2601"，标的 windCode "2601.HK"（某港股） → 用户找的是沪铜期货，该港股与铜无关

判断原则：仅有数字子串的巧合重合，而标的的品种/公司/行业与关键字的核心意图无关 → 过滤。一般语义查询中，标的的品种/公司/行业与核心意图存在实质关联 → 即使代码不匹配也可保留；但「名称 + 代码片段」复合查询必须按下方规则同时满足名称侧和代码侧，不能只靠名称或只靠代码保留。

## 第三步：过滤与排序

### 代码直接匹配优先规则

先判断关键字属于「纯代码/完整代码查询」还是「名称 + 代码片段的复合查询」，两类处理不同。

纯代码/完整代码查询：如果关键字整体就是代码，或关键字含完整带后缀代码（如 `0013.HK`、`600519.SH`、`AAPL.O`、`CU2601.SHF`），或只有代码加市场/交易品种修饰语（如 "0883 港股"、"600519 A股"），则代码是唯一核心意图。关键字能直接匹配到列表中某个标的的 windCode（去掉交易所后缀后比较，忽略大小写）时，该标的极大可能就是用户要找的目标：
- 匹配时忽略前导零差异：如关键字"00700"应能匹配 windCode "0700.HK"，关键字"0700"也应能匹配 windCode "00700.HK"
- 若只匹配到一个标的：直接返回该标的，过滤掉其他所有标的
- 若同一代码在多个交易所上市（如港股和A股都有）：返回该代码所有交易所的标的，过滤掉其他不相关标的
- 此规则优先级最高（**高于下方「结果精简 / 全部保留」**）——纯代码/完整代码查询代表用户明确知道自己要找什么；即便候选里有同一公司的跨市场版本，只要关键字给了精确代码，也只返回该代码对应标的、过滤掉其它市场的同名标的
- 若关键字同时含有概念词、行业词、修饰语（如"沪港通"、"主力合约"），且没有明确公司/品种名称，先判断这些词是否能与候选标的名称形成直接匹配：如果能直接匹配候选的 insShtDesc/insLngDesc，则按下方「名称/概念 + 代码片段」复合查询处理；如果不能直接匹配，只是宽泛描述性补充，才不作为独立搜索意图，仍仅返回该代码对应标的

名称/概念 + 代码片段的复合查询：如果关键字同时包含明确的公司/集团/品种名称、产品词、行业/概念词和数字代码片段，则必须从标的列表中找「名称侧符合」且「代码侧符合」的候选；只满足一侧的一律过滤，宁愿输出空数组也不要错选。
- 代码侧符合：windCode 去掉交易所后缀、忽略前导零后，与代码片段精确相等；或 windCode 主体包含该代码片段且结合名称侧可判定不是巧合；windCode 中的字母前缀不妨碍匹配；同一底层资产的不同交易币种/柜台/后缀证券（如 -R）也可视为代码侧符合
- 名称侧符合：insShtDesc 或 insLngDesc 与名称片段直接匹配，或是明确的简称/全称/同一底层资产/同集团核心业务强相关表达；行业/概念词只要在 insShtDesc 或 insLngDesc 中作为连续子串出现，也视为名称侧直接符合
- 同时满足名称侧和代码侧的候选才进入结果；其中代码精确匹配排第一，其它双侧符合候选按相关性排序
- 仅代码侧符合但名称侧无关 → 过滤；仅名称侧符合但代码侧无关 → 过滤；代码或名称任一侧不确定时也过滤
- 用户期望类型 predictedInsFamily 只能作为排序信号，不能过滤掉名称侧和代码侧都符合的候选

### 同品种合约格式去重（临时补丁）

当列表中同时存在同一品种的"月份字母+YY"格式代码（如 CLN26.NYM）和"YYMM"格式代码（如 CL2607.NYM），优先保留"月份字母+YY"格式的标的，过滤掉对应的"YYMM"格式标的。因为"月份字母+YY"格式是国际期货市场的标准活跃合约代码，代表更高的流动性和交易活跃度。

### 结果精简原则

尽量返回最少数量的高相关标的，避免返回大量模糊相关的候选：
- 当与用户核心意图相关的有效证券确实**只有一只**时，才只返回该标的；同代码多交易所、或**同一公司且同一交易品种**的多只有效证券都不算「只有一只」，须按下一条全部返回
- **「精简」只用于过滤掉与核心意图无关的巧合标的 / 不同公司或品种的标的。「全部保留」仅针对【同一公司且同一交易品种】的多只有效证券**——即核心名称相同（去掉 -U / -W / -WR 等份额/板块后缀后一致）、且**交易品种相同**的不同证券（不同 windCode / 特殊代码，如「XX-U」与「XX」、同板块下同一核心名对应多个 windCode），它们都是用户要找的，**绝不可因后缀或 windCode 不同就当重复精简、只留一只**。
  - **跨市场 / 跨品种的同名标的不在「全部保留」范围**：① 纯代码/完整代码查询时，严格按上方『代码直接匹配优先』——只返回该代码对应标的，其它市场/品种的同名标的一律过滤（即便是同一公司）；② 名称 + 代码片段的复合查询时，只保留名称侧和代码侧都符合的候选，精确代码命中的标的排第一；③ 用户只给名称、未给代码时，按相关度与用户期望品种排序，不同品种的同名标的不强制全留。
- 不要因为"可能相关"就大量保留，只保留有较高信心确认相关的标的

### 过滤规则
- 仅因代码中的数字子串与关键字中的数字巧合重合而出现，但标的本身（品种、公司、行业）与核心搜索意图无关 → 过滤
- 标的属于完全不同的品种、公司或行业，与关键字不存在合理的关联路径 → 过滤
- 当关键字的核心意图明确时（如包含具体品种名称或公司名称），以语义匹配为主要判据，不被表面的字符串重合误导
- 当关键字较模糊时（如纯数字"2601"且无品种名称修饰），对字符串匹配给予更多权重
- 如果你对某个标的是否与核心意图相关存在合理的不确定性（如可能的产业链关联），保留该标的

### 排序规则
对保留的标的按相关性从高到低排序：
- windCode 完全匹配 > 部分匹配（前提是匹配有实质意义）
- 品种/公司名称完全匹配 > 语义关联
- 期货合约代码中使用月份字母+YY格式（如GCZ26.CMX）的匹配优先级高于YYMM纯数字格式（如GC2612.CMX）
- 期货标的中，带有具体合约月份的合约（如 CU2609.SHF、RBZ26.SHF）排在不带日期的主力/次活跃合约（如 CU_M.SHF、CU_S.SHF）之前；主合约通常无法下单，仅在没有任何带日期合约时才保留
- 当关键字不含任何日期/合约月份信息，且列表中同时存在期货标的与非期货标的时，非期货标的优先排在期货标的之前
- **关键字未指定具体到期月份时（仅给出品种/交易所名等，无月份或日期信息），同品种的多个期货合约按合约到期日相对「当前日期」排序**：
  1. 先解析每个合约代码（或简称末尾）的到期年月：月份字母+YY 或 YYMM 格式，月份字母码见上文 F=1月…Z=12月；两位年份按「当前日期」就近补全为四位。
  2. 到期月份严格晚于「当前日期」所在月（即次月及以后）的合约为高优先级，按到期日由近到远升序排列——次月合约排第一，之后逐月顺延，跨年后继续顺延到下一年更晚的月份，**严禁在排完次月后回跳到年初月份**。
  3. 到期月份等于当前月或更早（含已过期）的合约为低优先级，整体排在全部高优先级合约之后，组内同样按到期日由早到晚升序排列。
  4. 代码中不含具体到期月份的主连/连续合约（如简称无年月数字）保留但排在最末。
- 当关键字未指明市场（未含「A股/港股/美股/港股通/深港通/沪港通」等市场词）、且存在多个分属不同市场但相关性相当的候选时，tradableNow=true（当前市场开盘）的标的优先于同等相关、tradableNow=false 的标的。这是「市场不确定」时的次要消歧信号，绝不能因 tradableNow=false 就把明确匹配用户意图的标的下沉或过滤——相关性永远是首要排序依据
- 当存在 hasPermission=false（当前对手/群无此品种交易权限）的候选时，把它们排在所有 hasPermission=true 的同等相关候选之后；这只是次要信号，绝不能因 hasPermission=false 就过滤掉该标的、或把明确匹配用户意图的标的下沉到无关标的之后——相关性永远是首要排序依据
- 当输入提供了「用户期望品种」（用户显式给出的交易品种，如 A股/港股/港股通/美股等）时，在相关度相当的多个候选间，优先 transactionTypes 包含该期望品种的候选；其优先级高于下面的「用户期望类型」和上面的市场消歧（用户显式说的品种 > 模型猜的类型、> 当前是否开盘），但仍低于代码精确匹配与名称匹配——相关度永远是首要主键；用户给了明确代码时以代码为准、期望品种不覆盖代码；期望品种为空则忽略本条
- 当输入提供了「用户期望类型」（取值 EQUITY=股票/FUND=基金或ETF/FUTURE=期货/INDEX=指数）、且候选里并存多种 insFamily 时，与期望类型一致的候选优先（次要信号，相关度仍主键；期望类型为空则忽略本条）。**【仅排序、绝不过滤】期望类型只决定同相关度候选之间的先后顺序：绝不能因某候选的 insFamily 与期望类型不一致，就把它过滤/删除——类型不符但与搜索意图相关的候选仍必须保留在结果数组里，只是排在类型一致的候选之后。相关性永远是首要排序依据。**
- 多个维度同时匹配的排在前面
