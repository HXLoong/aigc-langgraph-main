placeOrderQuantity(委托数量,数字,单位:股):

- **【极其重要】股和手不能共用一个字段**:
  * 用户明确说"股" → 只能填写`placeOrderQuantity`
  * 用户明确说"手" → **绝对禁止**填写`placeOrderQuantity`,必须填写`placeOrderQuantityHand`
  * 用户只给纯数字、未携带单位(如"下2000""数量2000""2000") → 归入`placeOrderQuantity`
- 从swap_query中提取如"2000股""下2000""数量2000"等,统一为数字。
- 如果原文明确是"手",则本字段必须为null。
- 未提供则为null。

placeOrderQuantityHand(委托数量手,数字,单位:手):

- **新增字段**: 专门承载"手"这个单位的委托数量。
- **核心规则**:
  * 用户明确说"100手" → `placeOrderQuantityHand = 100`, `placeOrderQuantity = null`
  * 用户明确说"4手" → `placeOrderQuantityHand = 4`, `placeOrderQuantity = null`
  * 用户明确说"100股" → `placeOrderQuantity = 100`, `placeOrderQuantityHand = null`
  * 用户只给纯数字"100" → `placeOrderQuantity = 100`, `placeOrderQuantityHand = null`

  * 将"100手"写入`placeOrderQuantity`
  * 将"100股"写入`placeOrderQuantityHand`
  * 不允许为了统一字段而把"手"自动改写成"股"
- 未提供则为null。

placeOrderQuantityTotal(总量,数字,单位:股):

- **关键字段**:表示要交易的总量,是所有账户数量的总和
- **适用场景**:仅当算法类型为POV时需要填写,配合placeOrderTotalPovPercent使用
- **提取规则**:
  * 确保为整数格式,去除"股"等单位
  * 所有订单对象必须使用相同的总量值
  * 当用户文本中明确提到"总共32000股"等表述时,可从文本提取
- 非POV算法或未提供总量则为null。

placeOrderTotalPovPercent(总单POV比例,数字):

- **新增字段**:表示整个总单的POV比例,用于后续按数量占比分配给各交易对手
- **关键说明**:此字段与placeOrderPovPercent的区别:
  * placeOrderTotalPovPercent:总单的POV比例(如3%)
  * placeOrderPovPercent:每个交易对手实际分配的POV比例,由后处理脚本自动计算
- **适用场景**:仅当算法类型为POV且**同时存在placeOrderQuantityTotal(总量)**时才需要填写
- **【极其重要】前置条件**:此字段**必须且只能**在总单场景下填写。判断总单场景的标准:**当前订单或quote_content中的订单存在placeOrderQuantityTotal(不为null,即明确显示了"总量"字段)**。如果不存在总量,此字段**必须为null**,POV比例应设置到placeOrderPovPercent
- **识别规则**(仅在确认为总单场景后才适用):
  * 识别"跟量X%"格式,如"跟量3%"placeOrderTotalPovPercent = 3
  * 识别"POV X%"格式,如"POV 15%"placeOrderTotalPovPercent = 15
  * 去除"%"符号,保留数值
- **重要**:所有订单对象必须使用相同的总单POV比例值
- **后处理逻辑**:当placeOrderQuantityTotal和placeOrderTotalPovPercent都存在时,后处理脚本会自动计算每个交易对手的placeOrderPovPercent:
  * placeOrderPovPercent = placeOrderTotalPovPercent × (placeOrderQuantity / placeOrderQuantityTotal)
- 当用户文本中明确提到总单POV比例时可提取
- 未识别到总单POV比例则为null。

placeOrderOrderDirection(委托方向,字符串,对应GoatsOrderDirection枚举):

- **枚举值只有4个**: BUY、SELL、SHORT_OPEN、SHORT_CLOSE,**绝对禁止**输出任何其他值(如"BUY_CLOSE"、"SELL_OPEN"等都是无效值!)
- **【极其重要】强制分步匹配流程**(必须按步骤顺序执行,**绝对禁止跳过步骤1直接匹配步骤2**):

  **步骤1(最先检查): 检查是否包含4字方向词**
  * 输入包含"买入开仓" → 输出"BUY",结束
  * 输入包含"买入平仓" → 输出"SHORT_CLOSE",结束 (**买入平仓=平空,不是BUY!**)
  * 输入包含"卖出开仓" → 输出"SHORT_OPEN",结束 (**卖出开仓=卖空,不是SELL!**)
  * 输入包含"卖出平仓" → 输出"SELL",结束 (**卖出平仓=卖出,不是SHORT_CLOSE!**)
  * 如果步骤1匹配到任何一个 → **直接输出对应值,不再执行步骤2和步骤3**

  **步骤2(仅当步骤1未匹配时): 检查2字方向词**
  * 输入包含"买入" → 输出"BUY",结束
  * 输入包含"卖出" → 输出"SELL",结束
  * 输入包含"卖空" → 输出"SHORT_OPEN",结束 (**卖空≠卖出,不是SELL!**)
  * 输入包含"平空" → 输出"SHORT_CLOSE",结束
  * 输入包含"做多" → 输出"BUY",结束
  * 输入包含"做空" → 输出"SHORT_OPEN",结束

  **步骤3(仅当步骤1和2都未匹配时): 检查1字方向词**
  * 输入包含"多" → 输出"BUY",结束
  * 输入包含"空" → 输出"SHORT_OPEN",结束

- **【极其重要】为什么必须先检查步骤1**:
  * "卖出开仓"包含子串"卖出",如果跳过步骤1直接匹配步骤2,会错误匹配"卖出"→SELL
  * "买入平仓"包含子串"买入",如果跳过步骤1直接匹配步骤2,会错误匹配"买入"→BUY
  * "卖出平仓"虽然最终也映射为"SELL",但它仍是**完整方向术语**,必须优先按步骤1整体识别,**禁止拆词后碰巧命中**
  * **必须先用步骤1的4字词完整匹配,排除后才能进入步骤2**
- **【极其重要】开平仓是完整术语,绝对禁止按字面拆分**:

placeOrderEndTime(算法结束时间,字符串,格式HH:MM):

- 当用户提供算法时间窗时解析;TWAP通常需要时间窗(必需)。

- **【重要】时间格式规范化要求**:
  * **强制格式**: 必须严格按照HH:MM格式输出(小时和分钟都必须是2位数)
  * **补零规则**:
    - 单位数小时必须补0: "9:00" → "09:00", "9:30" → "09:30"
    - 单位数分钟必须补0: "15:5" → "15:05", "9:5" → "09:05"
  * **错误示例**: "9:00", "9:30", "15:5" (缺少前导零)
  * **正确示例**: "09:00", "09:30", "15:05" (符合HH:MM格式)

- **格式化处理流程**:
  1. 从用户输入中提取时间(如"9:00", "9:30", "14:5")
  2. 检查小时部分是否为单位数,是则补0(9 → 09)
  3. 检查分钟部分是否为单位数,是则补0(5 → 05)
  4. 输出规范化后的时间("09:00", "09:30", "14:05")
  * **严禁12/24小时制推断**:用户输入"5:00"只能补零为"05:00",绝不能推断为"17:00";用户输入"1:00"只能补零为"01:00",绝不能推断为"13:00"。只做格式补零,不做语义纠正。

- **【最高优先级】时间窗提取流程**:
  1. 先按原文切分时间窗左右两侧(如"9:00-5:00"切为左侧"9:00"、右侧"5:00")
  2. 左侧时间只做补零后写入placeOrderStartTime
  3. 右侧时间只做补零后写入placeOrderEndTime
  4. **绝不交换左右两侧、绝不改写数值、绝不补"下午"语义**
  5. 即使右侧时间早于左侧时间,也必须保持原文语义: "9:00-5:00" → placeOrderStartTime="09:00", placeOrderEndTime="05:00"
  6. 时间顺序是否合法由下游校验负责,**不属于本节点**

- **两种时间表达方式**:
  * **绝对时间**:使用具体时间点(如"9:30-10:30"),填写此字段并规范化为HH:MM格式
  * **相对时间**:使用相对时长(如"TWAP十分钟"),填写placeOrderRelativeTimeMinutes字段,此字段为null

- 支持"HH:MM-HH:MM""HH:MM到HH:MM"格式:
  - 输入: "9:30-10:30" → 输出: placeOrderStartTime="09:30", placeOrderEndTime="10:30"
  - 输入: "14:00到15:30" → 输出: placeOrderStartTime="14:00", placeOrderEndTime="15:30"
  - 输入: "9:00-15:00" → 输出: placeOrderStartTime="09:00", placeOrderEndTime="15:00"

- **【新增】无冒号4位数时间格式(HHMM)支持**:
  * 用户有时使用不含冒号的4位数字表示时间(如"1500"表示15:00、"1530"表示15:30)
  * **转换规则**: 前2位为小时(00-23)，后2位为分钟(00-59)，在输出前插入冒号
    - "1500" → "15:00"
    - "1530" → "15:30"
    - "0930" → "09:30"
    - "1830" → "18:30"
  * **识别条件**: 两个4位数字通过"-"或"到"连接时（如"HHMM-HHMM"），且每部分的前两位在00-23之间、后两位在00-59之间，识别为时间窗
  * **示例**:
    - "1500-1700" → placeOrderStartTime="15:00", placeOrderEndTime="17:00"
    - "1530-1830" → placeOrderStartTime="15:30", placeOrderEndTime="18:30"
    - "0930-1500" → placeOrderStartTime="09:30", placeOrderEndTime="15:00"
    - "pov 1500-1700" → placeOrderAlgorithmType="POV", placeOrderStartTime="15:00", placeOrderEndTime="17:00"
    - "TWAP 1530-1830" → placeOrderAlgorithmType="TWAP", placeOrderStartTime="15:30", placeOrderEndTime="18:30"

- **重要**:时间窗中的数字只能解析为时间,不能解析为其他参数(如POV比例)。

- **示例**(注意时间格式规范化):
  - "pov 11:25-11:30" → placeOrderStartTime="11:25", placeOrderEndTime="11:30"
  - "POV25% 14:00-15:00" → placeOrderStartTime="14:00", placeOrderEndTime="15:00"
  - "9:00-15:00" → placeOrderStartTime="09:00", placeOrderEndTime="15:00" (补零!)
  - "9:00-5:00" → placeOrderStartTime="09:00", placeOrderEndTime="05:00" (只补零,不做下午推断!)
  - ❌ 错误示例: "9:00-5:00" → placeOrderStartTime="09:00", placeOrderEndTime="17:00" (错误!这是语义纠正,不是格式化)
  - "9:30-10:30" → placeOrderStartTime="09:30", placeOrderEndTime="10:30" (补零!)
  - "TWAP十分钟" → placeOrderStartTime=null, placeOrderEndTime=null, placeOrderRelativeTimeMinutes=10

- 特殊短语映射(已规范化为HH:MM格式):
  - "上午开盘后" → "09:30"
  - "下午开盘后" → "13:00"

- **【时间字段填充原则】**:placeOrderStartTime **仅当用户明确给出时间点时才填写**,否则输出null由系统处理
  * **必须填写**:用户给出明确的绝对时间（如"9:30"、"14:00"、"上午开盘后"等）
  * **必须输出null**:用户仅使用紧迫性词汇或直接操作词汇（如"现在"、"马上"、"立即"、"赶紧"、"直接"等），但未指定任何具体时间点——这类词汇**不是时间指定，不得填入now_date_time或任何时间值**
  * **后端兜底**:placeOrderStartTime=null 时，后端会自动填充当前时间，LLM无需介入

- 若仅给出开始/结束之一,则仅填对应字段(记得补零),另一字段为null。

    - **绝对禁止**:输出任何不在swap_query中的账户名（即使它在提示词示例中出现过）

【关键提醒:重复交易对手的独立订单处理】
在处理多行订单数据时,必须严格遵守以下规则:

1. **核心原则**: 每一行数据都对应一个独立的订单对象,无论交易对手是否重复

2. **严格禁止**:

   -  循环遍历时使用错误的终止条件,导致最后几行被遗漏

3. **正确处理**:

   -  逐行遍历所有数据行(从第2行到最后一行)
   -  为每一行创建一个独立的订单对象
   -  相同交易对手的不同数量视为不同的订单

   -  实际识别时必须且只能从原始输入(swap_query)中提取,**严禁套用**提示词中的任何示例数据

   - 绝不允许出现任何字符差异(中英混杂、字形相似但不同的字符等)
