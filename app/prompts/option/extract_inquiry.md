    12. 交易对手关键词: "交易对手:"/"账号"/"交易账号"/"交易账户" + 完整标识符

     c. 逐片段分类: 对每个片段独立判断属于哪个字段
     d. 取剩余: 排除所有已识别字段后,剩余片段就是 stockCode 候选
     e. 多个剩余片段时优先取代码格式

   3. stockCode 每个字符是否与原始输入逐字节完全相同?

2. optionType(期权类型):

     · 参与型 / 参与 / 参与型看涨 → "参与型看涨"

3. tenor(期限):
   - 【输出格式严格要求 — 极其重要】tenor 字段输出**必须是 "XM" 格式**（X 为正整数月份，M 必须大写）；询价接口**仅支持 M 单位**，不接受 Y/y/年/月/m
   - 单位归一化规则（必须在输出前完成，不允许把 Y/y/年/m 直接写到 tenor）:
     · 年 → 月（× 12）："1Y"/"1y"/"1年" → "12M"；"2Y"/"2年" → "24M"；"3年" → "36M"；以此类推
     · 月："1M"/"1个月"/"一个月" → "1M"；"3M"/"三个月" → "3M"；"6M"/"半年" → "6M"；"12M"/"一年" → "12M"
     · 纯数字（如 "1"、"12"，无单位）→ 补 M 后缀：→ "1M"、"12M"
     · 小写 m → 大写 M："1m"/"12m" → "1M"/"12M"
   - 中文期限识别（结果已归一化为 M）: "一个月"="1M"、"两个月"="2M"、"三个月"="3M"、"半年"="6M"、"一年"="12M"、"两年"="24M"、"三年"="36M"
   - 【输出反例 — 绝对禁止】:
     · ❌ tenor="1Y" / "1y" / "1年"（必须先按 ×12 转 "12M" 再输出，绝不允许保留 Y）
     · ❌ tenor="1" / "12"（必须补 M 后缀）
     · ❌ tenor="1m" / "12m"（必须大写 M）
     · ❌ tenor="1.5M" / "0.5M"（期权期限只能为正整数月份，不允许小数）


   【多期限 "/" 详细规则】
   "/"符号表示多个独立期限的组合,绝不是数学运算符:
   - "1/2M" → 两个独立期限 "1M" 和 "2M", 创建两个 orderList 对象
   - "1/3M" → "1M" 和 "3M"
   - "2/6M" → "2M" 和 "6M"
   - "1M/3M" → "1M" 和 "3M"
   每个独立期限对应 orderList 中的一个完整对象(其他参数相同)。


   【绝对禁止】
   - 把"1/2M"解释为"0.5M"或"1.5M"等小数期限
   - 生成任何小数期限,期权期限只能是整数月份/周数/年数

   - 多执行价"数字/数字+%": "100/103%" → 两个值 100/103 拆解为两个 orderList 对象
   - 【平值/平直关键词】: 若输入包含"平值"或"平直"(含紧黏写法如"平直看涨"、"平值雪球"),
     必须识别为 strikePercentage: 100.00
     · "平直看涨 1M" → strikePercentage: 100, optionType: "欧式看涨"
     · "平值雪球" → strikePercentage: 100, optionType: "雪球"
     · "中国平安平直看涨" → stockCode: "中国平安", strikePercentage: 100, optionType: "欧式看涨"
   - 平值识别优先于 stockCode 排除法: "平值"/"平直" 必须被识别为已知字段(strikePercentage 关键词),
     不能污染 stockCode 候选
   - 没有明确提供且无平值关键词 → null


5. notionalAmount(名义本金):
   - 从raw_content中提取
   - 格式: 数字字符串(单位转换后),如"1000000"
   - 单位识别:
     · "100万" → 1000000
     · "1W" / "1w" → 10000
     · "1000w" / "1000W" → 10000000
     · "1KW" / "1kw" → 10000
     · "1千万" → 10000000
     · "1亿" / "1E" / "1e" → 100000000
     · 中文数字: "两千万" → 20000000、"三千万" → 30000000
   - 用户可能分批补充参数,需要从历史中累积已补充的参数


6. participationRate(参与率):
   - 识别关键词: "参与率"、"参与比例" 及其后数字
   - "参与率: 90%" → 90.0
   - "参与比例 80%" → 80.0
   - 【极重要】严格区分: "POV25" 是 povRatio(本节点询价场景一般不涉及),
     不是 participationRate; 不要把 POV 数字识别为参与率


7. shortName(交易对手):
   - 【识别关键词】"交易对手:" / "交易对手" / "账号" / "交易账号" / "交易账户" 后接的完整标识符
   - 【典型标识符格式】数字+中文名+可选括号内容，如 "11125测试短名（张天琪专用）"、"10074测试短名"、"0099123"
   - 【无显式关键词也能识别】分隔符（中英文逗号/顿号/空格/换行）后剩余的"数字+中文"模式片段，即使没有"交易对手:"前缀，也应识别为 shortName（典型示例："博时央调ETF, 欧式看涨 1M, 80%, 11125测试短名（张天琪专用）" → 最后一个片段就是 shortName）


   【完整性保证 — 极其重要】
   - 必须保留括号（中文括号（） / 英文括号()）及其内全部内容，逐字符原样不动
   - 数字前缀必须完整保留（如 "11125"），不能拆走
   - 中英文括号类型必须与原始输入一致，绝不互换
   - ✅ 正例：
     · "11125测试短名（张天琪专用）" → shortName: "11125测试短名（张天琪专用）"
     · "11125测试短名(张天琪专用)" → shortName: "11125测试短名(张天琪专用)"
     · "交易对手:11125测试短名（张天琪专用）" → shortName: "11125测试短名（张天琪专用）"（去掉"交易对手:"前缀，保留完整内容）
     · "交易对手 11125测试短名(张天琪专用)" → shortName: "11125测试短名(张天琪专用)"
     · "账号 0099123" → shortName: "0099123"
   - ❌ 反例（绝对禁止）：
     · "11125测试短名（张天琪专用）" → shortName: "11125测试短名"（截断括号内容，错误）
     · "11125测试短名（张天琪专用）" → notionalAmount: "11125测试短名（张天琪专用）"（含中文/括号绝不是名义本金，严重错误）
     · "11125测试短名（张天琪专用）" → participationRate: 11125（数字前缀单独拆出当参与率，严重错误）
     · "交易对手:11125测试短名（张天琪专用）" → shortName: null（显式关键词存在却没识别，错误）


   【与 notionalAmount / participationRate 的严格区分】
   - 含中文字符或括号的片段 → 绝不能写入 notionalAmount（notionalAmount 只接受"纯数字+万/W/kw/千万/亿"等单位格式）
   - 含中文字符或括号的片段 → 绝不能拆出数字部分写入 participationRate
   - 一旦识别为 shortName 模式，整个片段（数字前缀+中文名+括号）必须**整体**写入 shortName 字段，不可拆解


   【选项格式 — 字母/序号回复】
   - 用户回复单字母（A/B/C）或序号（"第1个"/"第二个"）→ 从 quote_content 查找候选交易对手列表
   - 提取对应选项的完整名称（含所有括号内容），原样写入 shortName


   【未提供时】
   - 用户没明确提供交易对手 → shortName: null


   【与 strikePercentage / participationRate 字段的边界 — 极其重要】
   - shortName 段的新增规则**不影响** strikePercentage 与 participationRate 各自的提取逻辑：
     · "80%" / "100%" / "95%" 等**数字+%** 格式 → 严格走 strikePercentage（按上面第 4 节规则），**绝不**写入 participationRate
     · 只有当用户明确出现 "参与率" 或 "参与比例" 关键词时，相关数字才写入 participationRate；否则 participationRate 必须为 null
   - ❌ 反例：用户输入 "博时央调ETF，欧式看涨 1M, 80%, 11125测试短名（张天琪专用）"
     · 错误识别：strikePercentage=null, participationRate=80（把 80% 错塞给参与率）
     · 正确识别：strikePercentage=80, participationRate=null, shortName="11125测试短名（张天琪专用）"


【换标场景处理】
当用户输入单个字母(A、B、C等)或序号(第1个、第2个):
- 从quote_content中查找候选标的列表
- 提取对应的完整标的代码和名称


【补充参数场景】
当用户在补充之前缺失的参数时:
- 仅用raw_content中的新参数覆盖对应字段
- 保留历史中已提供的参数


【关键规则】
- 如果用户或上下文未明确提供 stockCode,该字段必须为 null
- 禁止通过模型知识库进行任何代码-名称映射或推断
- 多次询价: 只解析最后一次的输入,忽略之前的所有询价内容
- 没有明确提供的字段设为null


【多订单展开 - 最高优先级，先于输出格式执行】
当 tenor 或 strikePercentage 出现 "/" 分隔的多个值时，必须按笛卡尔积展开为多个 orderList 对象：
- orderList 对象数 = (tenor 值个数) × (strikePercentage 值个数)
- 每个对象除被展开的 tenor/strike 外，其余字段完全相同
- 展开示例（务必逐条产出，不得合并或丢失任何一单）：
  · "茅台 1M/3M 100%"    → 2 个对象：{tenor:"1M",strikePercentage:100}、{tenor:"3M",strikePercentage:100}
  · "茅台 1M 100/103%"   → 2 个对象：{tenor:"1M",strikePercentage:100}、{tenor:"1M",strikePercentage:103}
  · "茅台 1/3M 100/103%" → 4 个对象（2×2 笛卡尔积）


【输出前强制订单数自检 - 必须执行】
1. 数 tenor 串中 "/" 分隔出的期限个数 = T（无 "/" 则 T=1）
2. 数 strikePercentage 串中 "/" 分隔出的执行价个数 = S（无 "/" 则 S=1）
3. orderList.length 必须严格等于 T × S；不相等即为漏单，必须补全后再输出
