# Langfuse 节点中文名称与 LLM 标识

日期：2026-09-20。实现基于提交 f96e5ab。

## 显示规则

- 模型处理节点：`[LLM] 中文名称 [英文节点ID]`。该标识表示节点职责包含模型处理，仍可能先做代码检查；实际模型请求以其下 Generation 为准。
- 规则优先、模型兜底：`[Code/LLM] 中文名称 [英文节点ID]`。规则直接命中时不会新增 Generation。
- 确定性代码、后端 IO、子图：`中文名称 [英文节点ID]`；不因连接模型就统一加 LLM。
- 内部结构化处理链：`所属节点中文名 · 结构化处理链 [node_id/chain]`。
- 实际模型调用：`[LLM] 所属节点中文名 · 模型调用 [node_id/llm]`。
- 输出解析：`所属节点中文名 · 输出校验 [node_id/parser]`。
- 路由／重试耗尽：名称带所属业务节点，分别使用原路由函数名或 error_handler 后缀。
- 子图内部 LangGraph：`所属子图中文名子图 [node_id/graph]`；主图为 `交易指令处理 [main_graph]`。
- 未登记的第三方调用、已有用例 Trace 名称保持原名，不使用模型翻译名称。

## 实现与边界

统一清单：[node_labels.py](../app/observability/node_labels.py)。统一工厂：[tracing.py](../app/observability/tracing.py) 中的 `create_callback_handler()`。

服务端 `attach_request_trace`、harness callback 工厂及旧评测脚本 `_graph_callbacks` 已接入同一工厂。SDK 仍为 4.5.1，没有捆绑升级。

名字在开始回调中投影给原 SDK，不增加 Span/Runnable 包装，不在结束后更新名称。上下文按 run_id 存储，结束、异常、取消时清理；并行调用通过原始 langgraph_node 或父调用上下文确定归属。

英文节点键、函数名、路由、checkpoint、State、数据库和 HTTP 契约不变。Trace/Observation ID、父子关系、Session、模型名、Token、错误标记及原有脱敏配置保持原有行为。

每个观察记录新增以下 metadata，保留其他 metadata；修改的是副本：

- `otc_node_id`：所属英文业务节点 ID；无法确定则为空。
- `otc_node_label_zh`：中文职责；未登记则为空。
- `otc_original_run_name`：SDK 原始运行名称。

SDK 导出的 OTel 属性中可能以 `langfuse.observation.metadata.<字段>` 扁平表示；Langfuse API/UI 会将其呈现为 metadata。

新名称只影响新产生的观察记录，历史数据不改名。重启实际运行的 LangGraph 和评测进程后使用新代码。按 observation name 设置的 SaaS 手工筛选器需改用新名称，或根据保留的 original_run_name/node_id 调整；本次未修改 SaaS 已有筛选、评分器或告警。仓库检索未发现需要随本次改名调整的远端 Observation 名称过滤逻辑。
